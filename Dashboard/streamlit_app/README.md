# Дашборд школы Буркова (Streamlit)

Веб-версия аналитики из `main.ipynb`: те же расчёты (энтропия, косинусная
близость, PCA-траектория, тренды по годам), но вместо статичных PNG из
matplotlib/seaborn и виджетов ipywidgets — интерактивные графики Plotly,
которые открываются в обычном браузере.

## Структура проекта

```
streamlit_app/
├── app.py               # главный файл — запускать через streamlit run
├── analysis.py           # вся расчётная логика (перенесена из ноутбука)
├── charts.py              # построение графиков Plotly
├── data_io.py             # запросы к API школы Буркова + чтение/запись JSON
├── requirements.txt
├── .streamlit/config.toml # тема оформления + отключение опроса про email
├── Dockerfile              # сборка образа для Docker/Docker Desktop
├── .dockerignore
└── docker-compose.yml       # docker compose up --build — и всё готово
```

## Установка

Нужен Python 3.10+ (у вас 3.12, отлично подойдёт).

```bash
python3 -m venv venv
source venv/bin/activate        # на Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

```bash
streamlit run app.py
```

Появится ссылка вида `http://localhost:8501` — откройте её в браузере.
По умолчанию сервер слушает только localhost; если нужно открыть доступ
другим людям в локальной сети института, добавьте флаг:

```bash
streamlit run app.py --server.address 0.0.0.0
```

## Как загрузить данные

В боковой панели два варианта:

1. **«Загрузить готовые JSON»** — если вы уже прогнали разделы 1–2
   `main.ipynb` и у вас на диске лежат `factors.json`,
   `author_year_vectors_sid=….json`, `author_overall_vectors_sid=….json`,
   `author_fio.json` — просто перетащите их в соответствующие поля и
   укажите тот же `sid`, с которым они были получены.

2. **«Запросить через API»** — приложение само повторит логику ноутбука:
   загрузит справочник тем, погодовые и обобщённые профили авторов и их
   ФИО, с прогресс-барами вместо `interact_manual`. Нужен CSV со списком
   авторов (колонка `id`, как `file.csv` в ноутбуке) и доступ к сети,
   где виден `193.232.208.28`.

После загрузки появятся три вкладки:

- **Профиль автора** — тематический профиль, энтропия, топ-тема по
  годам, динамика энтропии, PCA-траектория в пространстве тем.
- **Сравнение авторов** — тепловая карта косинусной близости (с
  переупорядочиванием по кластерам), кластеризация, рейтинг
  разносторонности, ближайшие по тематике авторы к выбранному
  (число показываемых авторов регулируется ползунком).
- **Динамика школы** — топ тем школы, их динамика по годам (плюс явный
  выбор конкретных тем через мультиселект — по умолчанию топ выше),
  тренды (линейная регрессия, значимость), прогноз по отдельной теме
  на N лет вперёд, ядро vs периферия школы, активность школы по годам.

### Про «динамику топ-тем»

Слайдер «Количество тем в топе» задаёт топ-N по среднему весу за весь
период — это накопительный список (топ-3 всегда целиком входит в
топ-6), поэтому при увеличении числа на графике просто добавляются
новые линии, а уже показанные никуда не деваются и не меняют форму —
это ожидаемое поведение, а не баг. Под графиком показан явный список
тем и мультиселект — можно убрать/добавить любую тему вручную, чтобы
сразу увидеть, что изменилось.

Все графики интерактивны «из коробки» (zoom колесом мыши, наведение
курсора для подробностей, клик по легенде — скрыть/показать серию).

## Как показать это «на сайте»

- **Локально / в сети института**: запустить `streamlit run app.py
  --server.address 0.0.0.0` на машине с доступом к API и открыть порт
  8501 для нужных пользователей — получится настоящая веб-страница с
  дашбордом.
- **Встроить в существующий сайт**: Streamlit-приложение можно
  завернуть в `<iframe>` на любой HTML-странице, указав на его адрес.
- **Streamlit Community Cloud**: если данные не строго внутренние,
  можно бесплатно задеплоить репозиторий на share.streamlit.io — тогда
  получится публичная ссылка без необходимости держать свой сервер
  (учтите: там сначала нужно один раз локально сохранить нужные JSON и
  подгружать их через «Загрузить готовые JSON», либо давать доступ к API
  снаружи сети института, что может быть невозможно).

## Запуск через Docker (Docker Desktop)

В проекте есть `Dockerfile` и `docker-compose.yml` — можно не ставить
Python и зависимости на компьютер вообще, а просто собрать образ.

**Через docker compose (проще всего):**

```bash
cd streamlit_app
docker compose up --build
```

Откройте `http://localhost:8501`. Остановить — `Ctrl+C`, либо в Docker
Desktop нажать Stop на контейнере `burkov-school-dashboard`. Повторный
запуск без пересборки: `docker compose up`.

**Через обычные команды docker (то же самое руками):**

```bash
cd streamlit_app
docker build -t burkov-school-dashboard .
docker run -p 8501:8501 --name burkov-school-dashboard burkov-school-dashboard
```

**Через Docker Desktop (GUI, без терминала):**
1. Вкладка *Images* → *Build* (или просто выполните `docker build` один
   раз из терминала — дальше образ появится в списке).
2. Найдите образ `burkov-school-dashboard` → *Run*.
3. В настройках запуска укажите проброс порта: *Host port* `8501` →
   *Container port* `8501`.
4. После запуска откройте `http://localhost:8501`.

**Важно про данные.** Загрузка JSON/CSV через боковую панель
(«Загрузить готовые JSON» / «Запросить через API») работает точно так
же, как и без Docker — файлы идут через браузер по HTTP, контейнеру не
нужен прямой доступ к вашей папке. `.dockerignore` специально исключает
`*.json`, `*.csv` и `main.ipynb` из образа — они не нужны для работы
приложения и не должны туда попадать. Если хотите держать данные и
внутри контейнера (например, чтобы не грузить их через интерфейс каждый
раз заново), раскомментируйте `volumes:` в `docker-compose.yml` и
положите файлы в подпапку `data/` рядом с `docker-compose.yml`.

**Если нужен доступ к API школы Буркова из контейнера** (сценарий
«Запросить через API») — контейнер должен быть в той же сети, откуда
виден `193.232.208.28`. Если это внутренняя сеть института, а Docker
Desktop у вас на рабочем компьютере с VPN/прямым доступом — обычно всё
работает «из коробки», т.к. контейнер использует сетевой стек хоста
через NAT. Если API не отвечает изнутри контейнера — проще всего
собрать JSON-файлы локально через `main.ipynb` (как раньше) и загрузить
их в контейнеризированное приложение через «Загрузить готовые JSON».

## Что можно доработать дальше

- Кэширование (`st.cache_data`) для `fetch_*`-функций, если планируете
  часто перезапускать приложение с одними и теми же id/годами.
- Экспорт текущей вкладки в PDF/PNG — у каждого графика Plotly уже есть
  кнопка «скачать как PNG» в правом верхнем углу при наведении.
- Многостраничная навигация (`st/pages`), если разделов станет больше.
